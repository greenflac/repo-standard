# Доводка репозитория

Норма — `repo-standard.md` (лежит рядом). Прибор — `repo-lint`. Ты правишь; вердикт
выносит отдельный прогон по диффу, не ты (правило И1 харнеса).

## Порядок

1. **Прочитать состояние, а не угадать его.**
   ```
   python3 -m repo_lint <путь> --tier base --format json > /tmp/before.json
   python3 -m repo_lint <путь> --tier base
   ```
   Три числа в конце вывода — `проверено / нарушений / не смогли` — это точка отсчёта.
   Запиши их: без «до» не бывает «после» (И3).

2. **Ветка задачи.** Работать только в ней, никогда в `master`/`main` (Ц1). Прод-деплой
   в чужих репозиториях часто висит на пуше в основную ветку — чистка не повод его запускать.

3. **Разделить коммиты по классам правок** (К7). Порядок — от безопасного к спорному:
   1. `чистка: комментарии` — К1–К6: пересказы, закомментированный код, реплики диалога,
      штампы авторства, метки `TODO` без `DEBT(дата)`, отладочная печать;
   2. `чистка: мусор и раскладка` — С2–С4: артефакты разработки, рабочие записи в
      `docs/journal/`, служебные файлы вон из индекса;
   3. `доки` — Д1–Д5: README, индекс `docs/`, битые ссылки;
   4. `ci` — А1–А5: `permissions`, `concurrency`, пины действий, снятая маскировка красного;
   5. `безопасность` — Б1–Б2: секреты вон, пример конфигурации на месте.
   Поведение продукта в этих коммитах не меняется. Если правка меняет поведение —
   это отдельный коммит с отдельным обоснованием.

4. **Что удалять нельзя без спроса.** Файл, который может быть нужен на проде или
   в чужом процессе (скрипты деплоя, конфиги хостинга, генераторы), не удаляется —
   про него задаётся вопрос. Чужой модуль не редактируется вовсе (Ц2): если правка
   нужна там, она идёт в отчёт, а не в дифф.

5. **Каждое исключение из нормы — видимая запись.** Оставляешь нарушение осознанно —
   строка `# DEBT(ГГГГ-ММ-ДД): что не сделано и почему` рядом с местом и пункт в отчёте (Ц8).
   Молча пропущенное нарушение становится нормой.

6. **Повторный прогон и дельта.**
   ```
   python3 -m repo_lint <путь> --tier base
   ```
   В отчёт: было `N/M/K`, стало `N/M'/K'`, и чем именно закрыт каждый класс.
   Число «не смогли» не должно расти: выросло — значит, что-то сломалось, а не улучшилось.

7. **Проверить глазами то, что произвёл** (П3): открыть README и одну-две изменённые
   страницы целиком, не только дифф. Числа проходят у результата, который человек
   забракует за секунду.

## Чего делать нельзя

- Массовая переформатировка всего дерева «заодно» — она прячет содержательные правки
  и делает дифф нечитаемым.
- Удаление тестов, `skip`/`xfail`, `continue-on-error: true` и ретраи, чтобы получить
  зелёный CI (Т6, Т7, А5). Красное «не запускалось» и красное «упало» — разные вещи.
- Правка порогов прибора, чтобы нарушение исчезло. Порог меняется отдельным решением
  с обоснованием, а не в ходе чистки.
- Отчёт словами вместо вывода команды. «Готово» — только с приведённым выводом (И3).

## Публичная ступень

Репозиторий, который показывают наружу, проверяется `--tier public`: LICENSE,
`SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `CODEOWNERS`, шаблоны issue и PR,
CHANGELOG и теги SemVer, бейдж сборки, пины действий по SHA, `dependabot.yml`.
Проверка `Х1` всегда возвращает «не смогли»: защита ветки, обязательность ревью и смысл
README проверяются человеком — сворачивать их в «годно» запрещено (Р1).
