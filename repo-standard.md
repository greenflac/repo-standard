# Стандарт оформления репозитория — норма, проверяемая прибором

> Часть харнеса. Правила даны как императив плюс причина; у каждого правила есть код
> (`С2`, `К5`), и этот же код печатает прибор `repo-lint` — иначе правило нельзя нарушить
> наблюдаемо, а такое правило по Ц7 живёт до первого срока.
> Ступени две: **база** обязательна для любого репозитория, **публичный** добавляется
> флагом `--tier public` тем, что показывают наружу.
> Расхождение текста и прибора чинится в приборе, а не толкованием текста (Е2).

## Как это применяется

1. `repo-lint <путь>` печатает `проверено N / нарушений M / не смогли K` и коды возврата
   `0 / 1 / 2` — третий исход отдельный, потому что «ноль нарушений при нуле проверок» — не успех (Р1, Р2).
2. Skill `/repo-tidy` ведёт доводку: читает вывод прибора, правит, делит коммиты.
3. Вердикт выносит отдельный прогон по диффу, а не тот, кто чистил (И1).

## С. Структура и мусор

- **С1. Корень репозитория — витрина, а не рабочий стол.** Файлов в корне не больше
  `ROOT_FILES_MAX` (ВЫБРАНО: 25). Всё, что не нужно читателю в первую минуту, уходит в каталог.
  *Прибор: `С1 root-clutter`.*
- **С2. Артефакты разработки не лежат в дереве прода:** `preview-*`, `*-proto.*`, `*.bak`,
  `*.orig`, `*.rej`, `*.tmp`, `*~`, черновики. Они уезжают на прод при первом же деплое
  «по маске» и живут там годами. *Прибор: `С2 dev-artifacts`.*
- **С3. Рабочие записи сессий — не продукт.** `HANDOFF_*`, отчёты с датой в имени,
  аудиты, планы лежат в `docs/journal/` (или `docs/archive/`), не в корне и не вперемешку
  с документацией продукта. Читатель не должен отличать их вручную. *Прибор: `С3 worklog-placement`.*
- **С4. Сгенерированное и служебное не коммитится:** `__pycache__`, `node_modules`,
  `.DS_Store`, `Thumbs.db`, `*.log`, `.venv`. *Прибор: `С4 generated-tracked`.*
- **С5. `.gitignore` есть и покрывает мусор используемых в репо языков.** Отсутствие —
  причина С4, а не следствие. *Прибор: `С5 gitignore`.*
- **С6. Бинарь крупнее `BIG_BLOB_KB` (ВЫБРАНО: 1024 КБ) в git — решение, а не случайность:**
  либо LFS, либо вне репозитория, либо явная запись, почему он здесь. История хранит его вечно.
  *Прибор: `С6 big-blobs`.*
- **С7. Инструмент, не являющийся частью продукта, лежит в `tools/<имя>/` и самодостаточен** —
  свой README, свои зависимости, свой запуск. Иначе его нельзя вынести, и он врастает.

## К. Код и комментарии

- **К1. Комментарий отвечает «почему», а не «что».** Пересказ кода устаревает молча
  и обучает читателя не верить комментариям. *Прибор: `К1 comment-restates-code` — эвристика, ловит только комментарий,
  начинающийся с глагола пересказа («увеличиваем», «set», «call»); остальное остаётся человеку.*
- **К2. Закомментированного кода нет.** История — в git; закомментированный блок не
  компилируется, не тестируется и не удаляется никогда. *Прибор: `К2 commented-out-code`.*
- **К3. В комментариях нет следов диалога и рассуждений** — «теперь исправлено»,
  «как договорились», «я добавил», «финальная версия», упоминаний ассистента.
  Код читают люди, не знающие той переписки. *Прибор: `К3 chatter-comments`.*
- **К4. Авторство и дата — в git, не в шапке файла.** Скопированная шапка врёт с первой
  же правки. *Прибор: `К4 author-stamp`.*
- **К5. Незакрытая работа помечается одной формой: `DEBT(ГГГГ-ММ-ДД): что не сделано`**
  (правило Ц8 харнеса). `TODO`/`FIXME` без даты не грепаются и не стареют.
  *Прибор: `К5 todo-without-debt`.*
- **К6. Отладочная печать не попадает в ветку:** `console.log`, `print(` в библиотечном
  коде, `var_dump`, `dd(`. *Прибор: `К6 debug-output`.*
- **К7. Чистка и правка поведения — разные коммиты.** Смешанный дифф нельзя ни отревьюить,
  ни откатить; при откате чистки уезжает исправление.

## Д. Документация

- **Д1. README отвечает на четыре вопроса в первом экране:** что это, кому, как запустить,
  как проверить, что работает. Без команды запуска README — реклама. *Прибор: `Д1 readme-shape`.*
- **Д2. Обещание README проверяется командой.** Число, срок и «умеет» без команды,
  которая это печатает, — прогноз (И3). *Прибор: `Д2 readme-claims` (эвристика на числа без команды рядом).*
- **Д3. Раскладка `docs/` по жанрам ([Diátaxis](https://diataxis.fr/)): обучение, инструкция,
  справка, объяснение.** Смешанные жанры читаются как ни один из них. *Прибор: `Д3 docs-flat`.*
- **Д4. У `docs/` есть индекс `docs/README.md`**, и каждый документ достижим по ссылке
  из индекса или из другого документа. Документ-сирота не читают и не обновляют. *Прибор: `Д4 orphan-docs`.*
- **Д5. Относительные ссылки в markdown не битые.** *Прибор: `Д5 broken-links`.*
- **Д6. Архитектурные решения — короткие ADR в `docs/decisions/`** (формат MADR):
  контекст, решение, последствия. Решение, не записанное там, переизобретают.
- **Д7. Язык документа определяется его читателем и не смешивается внутри одного файла.**

## Б. Секреты и безопасность

- **Б1. Секретов в git нет** — ни в коде, ни в истории: приватные ключи, `.env`, пароли,
  токены. В репозитории только `*.example`. *Прибор: `Б1 secrets`.*
- **Б2. Пример конфигурации существует и перечисляет все обязательные переменные** —
  иначе «работает у меня» обнаруживается на чужой машине. *Прибор: `Б2 config-example`.*
- **Б3. Найденный в истории секрет считается скомпрометированным:** ротация, потом чистка
  истории. Удаление файла из HEAD ничего не отменяет.

## А. Автоматика и CI

- **А1. У каждого workflow задан `permissions:`** — по умолчанию GitHub даёт токену больше,
  чем нужно сборке. *Прибор: `А1 workflow-permissions`.*
- **А2. `pull_request_target` с checkout кода PR запрещён** — это выполнение чужого кода
  с секретами репозитория. *Прибор: `А2 dangerous-workflow`.*
- **А3. Действия запинены** — `uses: owner/action@<тег или SHA>`, никогда `@main`/`@master`.
  Плавающая ссылка меняет поведение сборки без коммита. *Прибор: `А3 unpinned-actions`.*
- **А4. `concurrency` задан** — иначе два пуша подряд гоняют и деплоят наперегонки.
  *Прибор: `А4 concurrency`.*
- **А5. `continue-on-error: true` на шаге проверки запрещён**, как и ретрай упавшего теста
  (Т7): это машинный способ выдать «не смогли измерить» за «прошло». *Прибор: `А5 green-washing`.*
- **А6. Красная сборка на основной ветке — работа сейчас, а не фон.**
- **А7. Всё, что обязано выполняться всегда, — хук, тест или CI, а не строка в этом файле** (Ц7).

## Ж. Публичная ступень (`--tier public`)

- **Ж1. `LICENSE` есть, и лицензия распознаётся SPDX.** Без неё код юридически закрыт
  для всех, включая тебя завтра. *Прибор: `Ж1 license`.*
- **Ж2. Есть `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `CODEOWNERS`.**
  *Прибор: `Ж2 community-files`.*
- **Ж3. Есть шаблоны issue и pull request.** *Прибор: `Ж3 templates`.*
- **Ж4. `CHANGELOG.md` в формате Keep a Changelog, теги по SemVer.** *Прибор: `Ж4 changelog`.*
- **Ж5. Бейдж состояния сборки в README указывает на реальный workflow этого репозитория.**
  *Прибор: `Ж5 ci-badge`.*
- **Ж6. Действия запинены по SHA (не по тегу) и включён `dependabot.yml`** — требование
  [OpenSSF Scorecard](https://github.com/ossf/scorecard/blob/main/docs/checks.md), проверки
  `Pinned-Dependencies` и `Dependency-Update-Tool`. *Прибор: `Ж6 sha-pinning`.*
- **Ж7. Лицензия стороннего артефакта проверена до встраивания** (Ц5); `non-commercial`
  и `research-only` помечаются отдельно.

## Что прибор проверить не может (исход «не смогли»)

Защита ветки, обязательность ревью, секреты в настройках репозитория, живость бейджа
в офлайне, смысл текста README. Эти пункты печатаются в `не смогли K` и проверяются
человеком — сворачивать их в «годно» запрещено (Р1).
