# repo-standard — норма оформления репозитория и прибор к ней

Три части, и порознь они не работают:

| часть | файл | что делает |
|---|---|---|
| норма | [`repo-standard.md`](repo-standard.md) | правила с кодами `С1`, `К5`, `А3`, `Ж1` — императив плюс причина |
| процедура | [`skills/repo-tidy/SKILL.md`](skills/repo-tidy/SKILL.md) | порядок доводки для агента: что чинить, в каком порядке, что нельзя трогать |
| прибор | [`repo_lint/`](repo_lint) | печатает `проверено / нарушений / не смогли` и красит сборку |

Документ без прибора отменяется под сроком (правило Ц7 харнеса), прибор без нормы
меряет непонятно что, поэтому код правила и код проверки — один и тот же символ.

## Как запустить

```
python3 -m repo_lint <путь к репозиторию>            # базовая ступень
python3 -m repo_lint <путь> --tier public            # плюс требования к публичному репо
python3 -m repo_lint <путь> --format json            # для CI и дельты «до/после»
```

Коды возврата: `0` — годно, `1` — есть нарушения, `2` — нарушений нет, но что-то
проверить не смогли. Третий исход отдельный: ноль нарушений при нуле отработавших
проверок — не успех (правила Р1, Р2).

## Как проверить, что прибор работает

```
make test      # тесты, включая негативный контроль на двух фикстурах
make mutate    # подмена констант-решений в обе стороны: тесты обязаны краснеть
make self      # прибор на собственном репозитории
```

Негативный контроль (правило И5) — две фикстуры: на `fixtures/clean` прибор обязан
молчать, на `fixtures/dirty` — шевельнуться по каждому классу нарушений отдельно.
Последний прогон: `fixtures/clean` — нарушений 0, `fixtures/dirty` — нарушений 22 из
24 проверок; пороговые проверки `С1` и `С6` меряются на собранных под порог
микро-репозиториях в тестах.

## Как подключить к харнесу

1. Клонировать репозиторий рядом с харнесом.
2. В `~/.claude/CLAUDE.md` добавить одну строку-ссылку: оформление репозитория — по
   `repo-standard.md`, доводка — skill `/repo-tidy`.
3. Скопировать или слинковать `skills/repo-tidy` в `~/.claude/skills/repo-tidy`.
4. В репозитории-клиенте добавить шаг CI `python3 -m repo_lint . --tier base` —
   норма начинает нарушаться наблюдаемо.

## Что прибор не проверяет

Защиту ветки, обязательность ревью, секреты в настройках репозитория и смысл текста
README. Эти пункты печатаются в `не смогли` и остаются человеку — сворачивать их в
«годно» запрещено.
